# Приложение аутентификации с использованием Refresh токена.

## Запуск
В корне проекта прописать команду: **docker-compose up --build**.
Приложение работает на порту прописанном в файле docker-compose.uml. (По умолчанию 5000)</br>
Логин и пароль для аутентификации: **admin admin**

## Алгоритм обновления токена

- При первоначальном входе с использованием логина и пароля, приложение сохраняет в cookie пару access и refresh токенов.
- Refresh токен хранится в БД в захешированном виде.
- При последующих доступах, к защищённому эндпоинту (**/privacy**), токен доступа достается из cookie и добавляется в заголовок к запросу</br>
- Перед истечением срока жизни токена доступа, отправляется запрос на обновление токена доступа. 
- Из cookie берутся 2 токена (доступа и обновления) обновляются и записывается новая пара токенов. </br>

_В данный момент механизм обновления токенов работает через кнопку, дабы долго не ждать автоматического обновления_

## Для чего сделано?

Данный механизм предназначен для обеспечения безопасного обмена сообщениями между клиентом и сервером.
При перехвате токена доступа (он короткоживущий), злоумышленник получает доступ к системе только на небольшой промежуток времени.
При перехвате токена обновления (он одноразовый), пользователь заметит это когда сам сделает обновление токена, токены сбросятся и прийдется заходить в систему используя логин и пароль.
Сброс токена происходит при передаче логина в теле запроса на обновление токена.

## Краткое описание программы.

- Единая точка в входа в программу это файл **Program.cs**. </br>
Там происходит регистрация всех классов и добавление промежуточного обеспечения (данная цепочка выполняется для каждого запроса).
- Эндпоинты для входа и обновления токенов (**api/authentication/login** и **api/authentication/refresh**) расположены в файле **Controllers/v1/AuthenticationController.cs** 
- Логика обновления токена в файле **Services/AuthenticationService.cs**
- Запросы к базе данных (используется EntityFramework) в Db/AuthenticationRepository.cs
- промежуточное обеспечение (middleware) для обработки ошибок и добавления токенов в header запроса расположено в папке Middlewares.
- Модели данных в папке Models.
- В файле конфигурации приложения (appsettings.json) расположены настройки токенов и строка подключения к БД.
- Скрипты для вызова запросов на аутентификацию и обновление токенов расположены в файле wwwroot/js/site.js
- Frontend реализован через Razor pages (для меня был самый простой вариант). страница находятся в папке Views.
**Shared/Layout.cshtml** - это основной шаблон для всех страниц. Страницы расположены в папке **Home**. Данные страницы отдает контроллер - HomeController в папке ./Controllers/v1
